# Экосистема заказов и профилей (18.11.2026)

**Принцип:** один человек — один профиль, один заказ — одна карточка везде.
**Главный канал — Telegram.** Клиентов из ВКонтакте аккуратно переводим в Telegram, а тех, кто
не хочет переходить, обслуживаем во ВК автоматически.

Почему это понадобилось. 17.11 покупательница купила код Robux на сайте, войдя через ВКонтакте,
а в поддержку написала из Telegram. Получилось два профиля, у телеграмного заказов нет, поэтому
не было ни закрепа, ни ответа по делу. Замер 18.11: из 1 969 профилей и Telegram, и ВК есть
только у **11**.

Мокап экранов: canvas «Экосистема заказов RobloxBank» (приватный, ссылка в HANDOFF).

## Э1. Ссылка привязки

- **Токен** — `TelegramWebLoginChallenge` с `mode = "bind"`: та же таблица, что у входа через
  бота. Живёт 7 дней, одноразовый, в базе только sha256. Новый токен гасит старые
  неиспользованные этого же профиля.
- **Кто выпускает.** Сайт — только для профиля текущей сессии (`POST /api/account/bot-bind`,
  админам запрещено). ВК-бот — для профиля самого написавшего.
- **Что делает бот на `/start ln_…`.** Гасит токен, затем вызывает
  `linkOrMergeVerifiedIdentity(target, {TG, tgId}, "bot-bind-token")`. Если у этого Telegram
  уже есть свой профиль, он вливается в целевой: заказы, коды, контакты, бонусы, `contactEmail`.
  Потом бот отвечает «Узнали вас» и показывает «Мой заказ».
- **Отказы** (`bindFailureText`): у профиля уже другой Telegram или площадки пересекаются —
  человеку предлагаем написать @RobloxBank_PA, склейка ручная.
- Старый путь `web_link_…` (виджет и 3 шага) оставлен для входа. В кабинете вместо него
  теперь кнопка `TelegramBindCard`.

## Склейка (`bots/shared/account-merge.ts`)

С 18.11 при склейке, кроме заказов WB, кодов WB, прямых намерений и идентичностей,
переезжают:
- `CodeOrder.creatorUserId`;
- `OrderContact` и `CodeOrderContact`: дубль по уникальному ключу удаляется, а связь «подключён
  к своему же заказу» гасится с пометкой `removedBy = "merge"`.

Методы в `AccountMergeAudit.evidence.method`: `bot-bind-token`, `admin-confirmed` (+ `by`).
Отклонённая пара — строка `AccountMergeAudit` со `status = "DISMISSED"`; в очереди она
больше не показывается.

## Э7. Очередь «похоже, один человек»

Улики (`buildMergePairs`):
- **сильная** — аккаунт сам нажал «Да, это мой заказ» на заказе другого профиля (контакт по
  коду, номеру покупки кода, пассу, нику или имени). Это может быть и родитель, поэтому решает
  админ;
- **слабая** — одно имя (порядок слов, регистр и ё не важны) у профиля только с Telegram и
  профиля только с ВК; хотя бы у одного должны быть заказы; если тёзок больше двух с каждой
  стороны, имя не считается.

Остаётся профиль с бо́льшим числом заказов, при равенстве — старший. Склеить нельзя, если
площадки пересекаются, это админ или служебный профиль. После склейки клиенту уходит одно
сообщение (`notifyPersonText`).

## Э3. Доставка

`tgThenVk(user, tgText, vkText)` в `src/lib/twa-notify.ts`: сначала Telegram; если он не доставил,
а ВК есть — сообщение уходит во ВК. На этом правиле:
- «выкуплено» (`notifyOrderCompleted`);
- региональная цена;
- rebind;
- пинг GP-watch;
- шаги покупателя.

Выбора основного канала клиентом пока нет: Telegram главный по решению владельца.

### З7. Эффекты и реакции (`bots/shared/tg-flair.ts`)

Эффекты на весь экран, только в радостные моменты:
- 🎉 код готов, заказ выкуплен, «нашли ваш заказ, подключили» (в поддержке), победа в розыгрыше;
- 🔥 геймпасс принят (уведомление с сайта);
- ❤️ отзыв принят, бонус на балансе;
- 👍 код карты WB активирован.

Эффекты бесплатные, ID проверены живьём 18.11.

Правила:
- В тихие часы 22–9 МСК эффектов нет (`effectExtra`).
- Если Telegram отказал именно из-за эффекта, сообщение уходит ещё раз без него (`withoutEffectOnError`).
- ВК эффектов не умеет.

Реакции бота на сообщения клиента:
- 👀 сразу, как прислал пасс, затем 🔥, когда пасс принят;
- 🙏 на скрин отзыва.

В поддержке:
- 👀 на сообщение клиента, когда диалог передан человеку — через `setMessageReaction` бизнес-подключения; если Telegram не даст, пишется в лог;
- ❤️ на «спасибо» — как раньше.

Розыгрыш в канале: перед итогами бот крутит 🎰 (`sendDice`), пауза 3,5 с.

Картинки рисует `node scripts/render-brand-cards.mjs`. Шлются файлом: сайт — через мост
`photo_base64`, бот — `{ source }`.

### Обращение на «вы»

Тексты ботов для клиентов переведены с «ты» на «вы»: местоимения, повелительное, глаголы 2-го лица,
прошедшее после «ты»; капс сохранён. Перевод сделан скриптом по строкам и проверен вручную.

Не тронуты:
- комментарии в коде;
- промпты ИИ (`pa-ai-support.ts` — там «ты» адресовано модели);
- открытки-подарки (`src/lib/codes/gift.ts`);
- реплики от лица клиента: «Ошибся с ником?», «🙈 Создал пасс, а бот его не видит».

Общий текст про ожидание теперь вызывается только с `robuxWaitText("vy")`.
