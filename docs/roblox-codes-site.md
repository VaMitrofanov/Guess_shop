# Коды активации Roblox на сайте — как устроено (14.11.2026)

## Статус (15.11.2026)

ключ склада в Coolify Web). Решение владельца: коды от поставщика ещё не пришли — продаём сейчас,

### Как перейти на мгновенную выдачу (когда придут коды)

1. Загрузить коды: `node --import tsx scripts/codes-import.ts <файл> <номинал> [метка]` (ключ склада —
   в `HANDOFF.md`), файл удалить.
2. Убрать `CODES_BACKORDER` в Coolify Web → рестарт (без пересборки: главная рендерится на запрос).
   Сайт сам вернёт «Robux за минуту», боты — «код придёт сюда сразу».
3. Пока флаг включён, код со склада всё равно выдаётся сам, если он там есть; ручная выдача —
   только для заказов, на которые кода не нашлось.

## Ручная выдача (15.11.2026)

Пока склад пуст, оплаченный заказ встаёт в `PAID` с пометкой `MANUAL_ISSUE`:

- покупателю — письмо «Оплата получена — готовим код» (у подарка — плательщику, не получателю)
  и, если заказ из бота, сообщение в чат; страница заказа опрашивает статус и сама покажет код;
- админам — «оплачен — выдать код вручную» в теме «Нужно действие» (`adminTargets`).

Выдача: `scripts/codes-issue.mjs` → `POST /api/internal/codes/issue` (HMAC `BOT_PAYMENT_API_SECRET`):

```
BOT_PAYMENT_API_SECRET=… node scripts/codes-issue.mjs queue
BOT_PAYMENT_API_SECRET=… node scripts/codes-issue.mjs issue CODE-XXXXXXXX <код> [номинал]
```

Одна транзакция: код ложится в склад сразу выданным (AES-256-GCM, дубль ловит HMAC), заказ получает
`ISSUED`; дальше та же доставка — письмо / открытка / кабинет / чат бота. Второй код на тот же заказ
не выдаётся (`already`), номинал можно сверить, код в ответе и логах не печатается.

## Подарок открыткой (15.11.2026)

`CodeOrder.deliveryMode = GIFT`, поля `gift*` (миграция `20261115_storefront2_gifts_reviews`).
Пожелание ≤140 символов, без ссылок и @ников (`validateGift`) — письмо уходит с нашего домена на
чужой адрес. Чек — на почту плательщика (адрес получателя для чека не используется: сюрприз).
Письмо-открытка без кода, кнопка «Открыть подарок» → `/gift/<токен>` (HMAC от id заказа, в базе
sha256) → код по кнопке (`/api/codes/gift`, `giftOpenedAt`). Отложенная отправка — `giftSendAt`,
отправляет тик `/api/internal/codes/tick`, который раз в минуту дёргает TG-бот.

## Коды в ботах (15.11.2026)

Тексты общие: `bots/shared/codes-shop.ts`; TG — `bots/tg/codes-shop.ts`, ВК — `bots/vk/codes-shop.ts`.
Бот не считает цены и не создаёт заказы сам — `POST /api/internal/bot-codes` (`view` / `order` /
`referral`, HMAC). Покупатель бота — тот же `User` (tgId/vkId), поэтому скидка и приглашения общие с
сайтом; бот-покупатель считается «зарегистрированным» (1%). Заказ из бота: `channel = TG|VK`,
`deliveryMode = ACCOUNT`; после выдачи Web шлёт код в чат (`src/lib/codes/chat-notify.ts`, TG — через
мост `/tg-proxy`, ВК — `messages.send`), повтор — тиком до 6 часов.

- Меню: ряд «🎟 Код Robux — сразу» / «🤝 Скидка за друзей», команды `/codes`, `/invite`, строка про коды
  в `/menu`. В ВК — payload `codes*` и текст «коды».
- Приглашение в бота: `t.me/RobloxBankBot?start=r_<код>`, `vk.me/club…?ref=r_<код>` — привязка по тем же
  правилам, что `/r/<код>` (только новый профиль, не сам себя, не после покупки).
- Ключ идемпотентности заказа — номинал + человек + окно 3 минуты: двойной тап не плодит заказы.

## Напоминание о неоплаченном заказе (15.11.2026)

Заказ кода без оплаты через час после создания получает ОДНО напоминание (`remindUnpaidCodeOrders`,
тик `/api/internal/codes/tick`): из бота — сообщение с кнопкой «💳 Оплатить», с сайта — письмо «ждёт
оплаты» (гостю на его почту, клиенту — на подтверждённую почту, для ссылки родителю — «напомните
родителю»). Отметка `CodeOrder.payReminderSentAt` ставится до отправки — второго не будет.

## Страница оплаты для родителя (15.11.2026)

`/pay/<токен>` у заказа, отправленного ссылкой (`createdVia = SHARE`), говорит с родителем: «Вам прислали
ссылку на оплату», заказ с плашкой «сумму и получателя изменить нельзя», «Что вы оплачиваете», «Наши
обещания», справа — «Проверьте нас сами» (отзывы WB, подписчики TG-канала и группы ВК, выдачи и Robux),
три 5★ отзыва WB, поддержка (Telegram + телефон), вопросы родителей, реквизиты ИП. Цифры живые
(`src/lib/trust-stats.ts`: пульс витрины + `getCommunityAudienceMetrics`, кэш час). Среднюю оценку WB не
показываем (≈3,9). Код — `src/app/pay/[token]/parent-trust.tsx`.

## Безопасность контура (дополнение 15.11.2026)

- `/api/internal/codes/{issue,queue,tick}` и `/api/internal/bot-codes` — только с HMAC-подписью тела и
  временем (±5 мин). Утечка `BOT_PAYMENT_API_SECRET` = возможность выдать код на оплаченный заказ и
  заводить заказы от имени tgId/vkId → секрет только в Coolify и `HANDOFF.md`.
- `/gift/<токен>` — как `/pay`: noindex, no-referrer, no-store; код только по POST с токеном в теле.
- На странице `/pay/<токен>` код по-прежнему не показывается тому, кто открыл ссылку; создателю,
  вошедшему в аккаунт, — по сессии (`/api/codes/reveal`).

## Три отдельных процесса

| Процесс | Где | Что не трогали |
|---|---|---|
| Новый код на сайте | блок `#codes` на главной → `/pay/<токен>` → письмо/кабинет | — |
| Оплаченная карточка WB | `/guide?source=wb` (кнопка «Ввести код» в первом экране и ссылка внизу блока кодов) | весь коридор WB |
| Геймпасс | калькулятор → `/checkout` | заказы, оплата, выкуп |

Активация кода — на `https://www.roblox.com/redeem` самим покупателем. Выдача кода магазином ≠
активация: интерфейс и письма это проговаривают.

**Округление (владелец, 14.11.2026):** копеек в цене нет. Сумма после скидки округляется ВВЕРХ до
рубля, кроме случая, когда рубли уже кончаются на 9 — тогда копейки просто отбрасываются, чтобы не
ломать «…9»: 3 999,03 → 3 999, 3 542,04 → 3 543 (`roundCodePriceKopecks`).

Сумму считает только сервер (`quoteCode`), в копейках, всегда целый рубль.
Номинал, база, процент, скидка и итог фиксируются в `CodeOrder` при создании и больше молча не
меняются; после истечения предложения (24 ч) нужна явная кнопка «Подтвердить за N ₽».

## Скидка за приглашения

**С 15.11.2026: базовый 1 % = регистрация + подписка на наш канал** (решение владельца — копить трафик в
канал). Подписка проверяется по-настоящему (`src/lib/codes/subscription.ts`): аккаунт с Telegram —
`getChatMember` канала `@Roblox_Bank_Tg` через мост TG-хоста, аккаунт с ВК — `groups.isMember` группы
`bankroblox`; засчитывается любой. Кэш на `User.channelSubscribed/channelCheckedAt` (да — 12 ч, нет —
5 мин), «Я подписался» на сайте и «✅ Я подписался» в ботах проверяют сразу. Аккаунт только с почтой —
предлагаем привязать Telegram. Уровни за друзей (2–5 %) от подписки не зависят.

Прежнее правило: 1 % сразу после регистрации; 3 / 10 / 20 / 30 засчитанных покупателей → 2 / 3 / 4 / 5 %. Уровни
заменяют друг друга. Засчитан = аккаунт, привязанный по ссылке `/r/<код>` (подписанная кука
`rb_ref`, 30 дней; привязка один раз и только НОВОМУ аккаунту), у которого есть выданный и не
возвращённый заказ кода, оплаченный после привязки. Счётчик не хранится — считается запросом
(`countQualifiedInvites`), поэтому повторный webhook не добавляет, а возврат сам убирает.
На витрине крупно — номинал Robux, цена вторым планом; пакет с самой низкой ценой за 1 R$
среди доступных помечен «Выгоднее всего» с ценой за 1 R$ (цифра из той же цены).
Создатель заказа = тот, кто оформил; родитель, оплативший по ссылке, на счёт не влияет и
аккаунт по его email не создаётся. Программа только для кодов.

## Данные (миграция `20261114_activation_codes_store`, аддитивная)

- `CodeOrder` — заказ: `publicId` (`CODE-XXXXXXXX`), суммы, создатель или `recipientEmail`
  гостя, `payTokenHash`, статус `AWAITING_PAYMENT → PAYMENT_PENDING → ISSUED` (или `PAID` при
  пустом складе, `REFUNDED`), срок предложения, отметки письма и показа кода.
- `CodePayment` — попытка оплаты, OrderId у банка `CODE-…-N`, свой email для чека.
- `ActivationCode` — склад: значение только в AES-256-GCM (`ACTIVATION_CODE_ENCRYPTION_KEY`),
  дубли по HMAC; `IN_STOCK → RESERVED (2 ч) → ISSUED`.
- `CodeOrderEvent` — журнал с ключами идемпотентности.
- `User.referralCode / referredById / referredAt`.

Почему не `WbOrder`: там `PENDING` — очередь выкупа геймпасса, оплаченный код попал бы в очереди
админов и ботов.

## Поток денег

1. «Оплатить» → резерв кода (`FOR UPDATE SKIP LOCKED`) → `Init` Т-Банка (тот же терминал, чек
   и классификаторы не менялись) → банк.
2. `/api/webhooks/tinkoff`: подпись и терминал как раньше; `OrderId` с `CODE-` уходит в
   `handleCodePaymentNotification` — сверка PaymentId, суммы, валюты, перехода статуса; код
   выдаётся в той же транзакции, что фиксирует оплату. Возврат браузера ничего не подтверждает.
3. После коммита — письмо (`sendCodeEmail`). Упало — заказ остаётся `ISSUED`, ошибка в
   `emailLastError`, кнопка «Отправить письмо ещё раз» шлёт тот же код.
4. Нет кода после оплаты / второй платёж по оплаченному заказу → пуш в «Уведы» (тема «Нужно
   действие»), деньги — ручной возврат.

Время в сырых SQL склада — только параметром из приложения (не `NOW()`): колонки без пояса,
Prisma пишет UTC. Сквозной тест поймал, что при поясе сессии ≠ UTC последний код уходил двоим.

## API

`GET /api/codes/catalog` · `POST /api/codes/orders` (`self` | `share`) · `POST /api/codes/pay` ·
`POST /api/codes/status` · `POST /api/codes/refresh` · `POST /api/codes/resend` ·
`POST /api/codes/reveal` (только создатель, по сессии) · `GET /r/<код>`. Токен ссылки — всегда в
теле запроса, кроме самого адреса страницы `/pay/<токен>`.

## Склад

```
node --import tsx scripts/codes-import.ts <файл> <номинал> [метка] [--dry-run]
```

Файл — по коду в строке; скрипт печатает только счётчики, дубли отсекает. Файл после загрузки
удалить. Интерфейса склада в TWA пока нет (этап K5 плана).

## Проверки перед выкатом (14.11.2026)

Локальная Postgres + подставной Т-Банк и SMTP, продовая сборка: 51 сквозной сценарий (оплата,
повторный webhook, подмена суммы/подписи, гонка за последний код, просрочка, ошибка банка,
сбой письма и повторная отправка, рефералы и возвраты, чужой код), матрица 47 «номинал × скидка»
до суммы в банке, 23 визуальные проверки (360/390/768/1440, обе темы, клавиатура). Найдено и
исправлено: время резерва в SQL зависело от пояса сессии БД (последний код уходил двоим).
