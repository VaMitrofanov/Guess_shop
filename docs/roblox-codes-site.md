# Коды активации Roblox на сайте — как устроено (14.11.2026)

**Продажа ОТКРЫТА 15.11.2026 в ручном режиме** (`CODES_SALES_ENABLED=true`, `CODES_BACKORDER=true`,
ключ склада в Coolify Web). Решение владельца: коды от поставщика ещё не пришли — продаём сейчас,
оплаченные заказы закрываем вручную постфактум. Чек — прежний («Цифровая услуга по заказу»).

### Как перейти на мгновенную выдачу (когда придут коды)

1. Загрузить коды: `node --import tsx scripts/codes-import.ts <файл> <номинал> [метка]` (ключ склада —
   в `HANDOFF.md`), файл удалить.
2. Убрать `CODES_BACKORDER` в Coolify Web → рестарт (без пересборки: главная рендерится на запрос).
   Сайт сам вернёт «Robux за минуту», боты — «код придёт сюда сразу».
3. Пока флаг включён, код со склада всё равно выдаётся сам, если он там есть; ручная выдача —
   только для заказов, на которые кода не нашлось.

## Ручная выдача (15.11.2026)

Пока склад пуст, оплаченный заказ встаёт в `PAID` с пометкой `MANUAL_ISSUE`:

- покупателю — письмо «Оплата получена — готовим код» (у подарка — плательщику, не получателю)
  и, если заказ из бота, сообщение в чат; страница заказа опрашивает статус и сама покажет код;
- админам — 🟠 «оплачен — выдать код вручную» в теме «Коды» (`adminTargets`); 🟠, а не 🔴: оплата прошла, это обычная работа (17.11.2026). 🔴 — только аварии: «кода на складе нет», второй платёж. Звонит и в тихие часы.
  **До 16.11.2026 этот алерт не доходил ни разу**: в подсказке стояло голое `<код>`, Telegram
  отклонял HTML целиком («can't parse entities: Unsupported start tag»), ошибка только в логе Web.
  Первым пострадал CODE-827TX8XJ (оплачен 15.11, покупательница написала сама). Теперь угловые
  скобки экранированы, а `notifyCodeAdmins` при отказе Telegram повторяет алерт простым текстом
  (`plainForTelegram`); тест `codes-admin-notify` не пропустит голые `<…>` в подсказках вебхука.
- **С 16.11.2026 — своя тема «Коды»** в беседе «Уведы» (`AdminTopic` `codes`, со звуком, копия в
  личку PA). Все алерты `notifyCodeAdmins` идут туда; пока темы нет — в личку ADMIN_IDS.
- **Выдача из темы «Коды»** (`bots/tg/codes-issue-reply.ts`). Под алертом «оплачен — выдать код
  вручную» (и «кода на складе нет») — кнопка «🎟 Выдать код N R$» (`cdi:<publicId>`, шлёт Web, ловит
  TG-бот — бот один и тот же). Нажал → бот просит код (`force_reply`) → ответ кодом → бот зовёт
  `/api/internal/codes/issue` (подпись `BOT_PAYMENT_API_SECRET`) и переписывает алерт в «🟢 код
  выдан · 🔑 код под спойлером · @кто · ЧЧ:ММ · 📬 письмо ушло», кнопку снимает. Сообщение админа
  с кодом бот заменяет СВОЕЙ копией «🔑 Код выдан · CODE-… · ‖код‖ · прислал @кто» (код под
  спойлером — виден по тапу, но не светится; владелец 16.11: «нужно видеть, какой код отправили»).
  Оригинал убирается только после того, как копия встала; при отказе копия — «⚠️ Код НЕ выдан ·
  причина», подсказка остаётся для следующей попытки. Отказ — с
  причиной (номинал, дубль кода, уже выдан…). Так же работает ответ кодом прямо на алерт и
  `/issue CODE-XXXXXXXX <код>`. `/codes` в беседе (или `/codes_queue` где угодно) — очередь
  оплаченных без кода с кнопкой на каждый. В алерте — куда уйдёт код (почта / кабинет / чат бота /
  открытка), без самого адреса. `scripts/codes-issue.mjs` — запасной путь.
- Письмо с кодом (`buildCodeEmail`) с 16.11 — **подарочная карта**: тёмно-фиолетовое «лицо» с
  номиналом и серийной строкой «№ CODE-…», линия отрыва, код в рамке, кнопка «Активировать на
  Roblox →», 3 шага, записка «Спасибо, что выбрали нас… — Команда RobloxBank». Если код выдан
  вручную позже 30 мин после оплаты (`waited`), — строка «Спасибо за терпение — этот код мы
  готовили для вас вручную». Только таблицы и инлайн-стили (почтовики режут `<style>`).
  До 16.11 письмо с кодом на проде не уходило ни разу (выданных заказов 0).
- Кнопка меню ботов — «🎟 Код Robux» (было «— сразу»: при ручной выдаче вводило в заблуждение);
  старую подпись бот по-прежнему понимает (`CODES_MENU_BTN_LEGACY`).

Выдача: `scripts/codes-issue.mjs` → `POST /api/internal/codes/issue` (HMAC `BOT_PAYMENT_API_SECRET`):

```
BOT_PAYMENT_API_SECRET=… node scripts/codes-issue.mjs queue
BOT_PAYMENT_API_SECRET=… node scripts/codes-issue.mjs issue CODE-XXXXXXXX <код> [номинал]
```

Одна транзакция: код ложится в склад сразу выданным (AES-256-GCM, дубль ловит HMAC), заказ получает
`ISSUED`; дальше та же доставка — письмо / открытка / кабинет / чат бота. Второй код на тот же заказ
не выдаётся (`already`), номинал можно сверить, код в ответе и логах не печатается.

## Подарок открыткой (15.11.2026)

`CodeOrder.deliveryMode = GIFT`, поля `gift*` (миграция `20261115_storefront2_gifts_reviews`).
Пожелание ≤140 символов, без ссылок и @ников (`validateGift`) — письмо уходит с нашего домена на
чужой адрес. Чек — на почту плательщика (адрес получателя для чека не используется: сюрприз).
Письмо-открытка без кода, кнопка «Открыть подарок» → `/gift/<токен>` (HMAC от id заказа, в базе
sha256) → код по кнопке (`/api/codes/gift`, `giftOpenedAt`). Отложенная отправка — `giftSendAt`,
отправляет тик `/api/internal/codes/tick`, который раз в минуту дёргает TG-бот.

## Коды в ботах (15.11.2026)

Тексты общие: `bots/shared/codes-shop.ts`; TG — `bots/tg/codes-shop.ts`, ВК — `bots/vk/codes-shop.ts`.
Бот не считает цены и не создаёт заказы сам — `POST /api/internal/bot-codes` (`view` / `order` /
`referral`, HMAC). Покупатель бота — тот же `User` (tgId/vkId), поэтому скидка и приглашения общие с
сайтом; бот-покупатель считается «зарегистрированным» (1%). Заказ из бота: `channel = TG|VK`,
`deliveryMode = ACCOUNT`; после выдачи Web шлёт код в чат (`src/lib/codes/chat-notify.ts`, TG — через
мост `/tg-proxy`, ВК — `messages.send`), повтор — тиком до 6 часов.

- Меню: ряд «🎟 Код Robux — сразу» / «🤝 Скидка за друзей», команды `/codes`, `/invite`, строка про коды
  в `/menu`. В ВК — payload `codes*` и текст «коды».
- Приглашение в бота: `t.me/RobloxBankBot?start=r_<код>`, `vk.me/club…?ref=r_<код>` — привязка по тем же
  правилам, что `/r/<код>` (только новый профиль, не сам себя, не после покупки).
- Ключ идемпотентности заказа — номинал + человек + окно 3 минуты: двойной тап не плодит заказы.

## Напоминание о неоплаченном заказе (15.11.2026)

Заказ кода без оплаты через час после создания получает ОДНО напоминание (`remindUnpaidCodeOrders`,
тик `/api/internal/codes/tick`): из бота — сообщение с кнопкой «💳 Оплатить», с сайта — письмо «ждёт
оплаты» (гостю на его почту, клиенту — на подтверждённую почту, для ссылки родителю — «напомните
родителю»). Отметка `CodeOrder.payReminderSentAt` ставится до отправки — второго не будет.

## Страница оплаты для родителя (15.11.2026)

`/pay/<токен>` у заказа, отправленного ссылкой (`createdVia = SHARE`), говорит с родителем: «Вам прислали
ссылку на оплату», заказ с плашкой «сумму и получателя изменить нельзя», «Что вы оплачиваете», «Наши
обещания», справа — «Проверьте нас сами» (отзывы WB, подписчики TG-канала и группы ВК, выдачи и Robux),
три 5★ отзыва WB, поддержка (Telegram + телефон), вопросы родителей, реквизиты ИП. Цифры живые
(`src/lib/trust-stats.ts`: пульс витрины + `getCommunityAudienceMetrics`, кэш час). Среднюю оценку WB не
показываем (≈3,9). Код — `src/app/pay/[token]/parent-trust.tsx`.

## Безопасность контура (дополнение 15.11.2026)

- `/api/internal/codes/{issue,queue,tick}` и `/api/internal/bot-codes` — только с HMAC-подписью тела и
  временем (±5 мин). Утечка `BOT_PAYMENT_API_SECRET` = возможность выдать код на оплаченный заказ и
  заводить заказы от имени tgId/vkId → секрет только в Coolify и `HANDOFF.md`.
- `/gift/<токен>` — как `/pay`: noindex, no-referrer, no-store; код только по POST с токеном в теле.
- На странице `/pay/<токен>` код по-прежнему не показывается тому, кто открыл ссылку; создателю,
  вошедшему в аккаунт, — по сессии (`/api/codes/reveal`).

## Три отдельных процесса

| Процесс | Где | Что не трогали |
|---|---|---|
| Новый код на сайте | блок `#codes` на главной → `/pay/<токен>` → письмо/кабинет | — |
| Оплаченная карточка WB | `/guide?source=wb` (кнопка «Ввести код» в первом экране и ссылка внизу блока кодов) | весь коридор WB |
| Геймпасс | калькулятор → `/checkout` | заказы, оплата, выкуп |

Активация кода — на `https://www.roblox.com/redeem` самим покупателем. Выдача кода магазином ≠
активация: интерфейс и письма это проговаривают.

## Цены (`bots/shared/codes-pricing.ts`, политика `retail-codes-v3`, 20.11.2026)

**Цена идёт за курсом доллара.** Прайс владельца посчитан при **85 ₽/$**
(`CODES_REFERENCE_USD_RUB`): поставщику платим в долларах, комиссия банка и налог — процент от
цены, поэтому цена × `курс / 85` сохраняет маржу каждого номинала в процентах. Курс —
поле **«USD → RUB» в Настройках TWA** (`GlobalSettings.usdToRub`), ставится вручную (решение
владельца: не ЦБ). Курс вне 60–150 считается опечаткой — берётся 85. На сервере курс кэшируется
на минуту (`src/lib/codes/usd-rate.ts`), сохранение настроек сбрасывает кэш. Округление базы:
номиналы до 1 000 R$ — плавно, до рубля; от 1 000 R$ — до ближайшей цены на …9.

| R$ | База при 85 ₽/$ | Что выдаём |
|---:|---:|---|
| 10 | 59 ₽ | код 10 |
| 50 | 189 ₽ | код 50 |
| 100 | 229 ₽ | код 100 |
| **199** | 359 ₽ | **код поставщика на 200** — аккаунт РФ получает 199 после конвертации |
| 500 | 659 ₽ | код 500 |
| 800 | 999 ₽ | код 800 |
| 1 000 | 1 199 ₽ | код 1 000 |
| **2 000** | 2 349 ₽ | **два кода по 1 000** |
| 2 500 | 2 999 ₽ | код 2 500 |
| 4 500 | 5 299 ₽ | код 4 500 |
| 5 250 | 5 999 ₽ | код 5 250 |
| 10 000 | 10 499 ₽ | код 10 000 |

**Номинал товара ≠ номинал кода поставщика** (`CODE_COMPONENTS` / `codeComponents`). Заказ
хранит номинал товара (`CodeOrder.denomination` = 199 / 2 000), склад — номиналы поставщика
(`ActivationCode.denomination` = 200 / 1 000; импорт принимает только их —
`isSupplierCodeDenomination`). Резерв и выдача (`reserveCodesForOrder` / `issueCodesForOrder`)
берут по коду на каждую часть — **все или ни одного**: неполный набор уходит на ручную выдачу
целиком. Все коды заказа — `ActivationCode` со статусом ISSUED и `reservedForOrderId` = заказ
(`issuedCodesForOrder`); `CodeOrder.activationCodeId` — первый код, признак «выдан». Письмо, чат
бота, кабинет и страница подарка показывают каждый код отдельно (`/api/codes/reveal` и
`/api/codes/gift` отдают `codes[]` и `code` — коды через перевод строки). Заказы старой политики
`retail-codes-v2` (до 20.11) остаются «один код своего номинала» — в т.ч. старый «2 000».
Старый номинал «200» снят с продажи: продлить его неоплаченный заказ нельзя (`BAD_DENOMINATION`).

**Ручная выдача набора:** алерт пишет «📦 нужно: 2 кода по 1 000 R$», кнопка — «🎟 Выдать 2
кода по 1 000 R$»; админ присылает оба кода одним сообщением (каждый с новой строки / через
запятую). Не то число кодов → `count_mismatch`, ничего не выдаётся. Скрипт:
`codes-issue.mjs issue CODE-… КОД1,КОД2`.

**Подпись под полем почты** (`CODE_REGION_NOTES`): 199 — «Из-за региональных особенностей каждой
страны аккаунты РФ получат 199 Robux после конвертации.», 2 000 — «придут 2 кода по 1 000». Та же
строка — на карточке заказа в ботах.

**ВК:** inline-клавиатура ≤ 10 кнопок, поэтому кнопками 8 ходовых номиналов
(`CODES_VK_DENOMINATIONS`), остальные — строкой со ссылкой на сайт. В TG — все 12.

SEO-страницы (`/kupit-robuksy` и др.) рендерятся на запрос (`force-dynamic`), чтобы цены шли за
курсом. В статичных метаданных и OG-картинке цен за курсом нет («от 10 R$»).

**Округление (владелец, 14.11.2026):** копеек в цене нет. Сумма после скидки округляется ВВЕРХ до
рубля, кроме случая, когда рубли уже кончаются на 9 — тогда копейки просто отбрасываются, чтобы не
ломать «…9»: 3 999,03 → 3 999, 3 542,04 → 3 543 (`roundCodePriceKopecks`).

Сумму считает только сервер (`quoteCode`), в копейках, всегда целый рубль.
Номинал, база, процент, скидка и итог фиксируются в `CodeOrder` при создании и больше молча не
меняются; после истечения предложения (24 ч) нужна явная кнопка «Подтвердить за N ₽».

## Скидка за приглашения

### 🎁 Подарочная скидка (19.11.2026)

`CodeDiscountGrant` — разовая скидка одному человеку от нас (извинение, компенсация): `percent` (1–5),
`reason`, `note` (личные слова в кабинете), `grantedBy`, без срока (`expiresAt` — по желанию).
`viewerCodeDiscount` берёт БО́ЛЬШУЮ из обычной и подарочной (`withGift`, не складываются), поэтому
подарок сразу работает на сайте, в TG и ВК. При создании заказа, где подарок дал цену, он
резервируется за этим заказом (`usedOrderId`, перезаписывается последним), а тратится только
при ОПЛАТЕ (`webhook.ts`, `usedAt`). Бросил оплату — подарок цел. Видно: кабинет — карточка
«Подарок от нас» + значок в профиле; боты — строка «🎁 Подарок: −N% на один код» в витрине и
«🎁 подарок N%» на карточке номинала. Выдача — `scripts/code-gift-grant.mjs` (тексты — файлами
вне репозитория; есть `--dry-run`, повтор не дублирует).

**Открытка — «письмо» (вариант В, 19.11.2026).** `/gift/<токен>` больше не витрина, а праздник:
фон и гирлянда в цвет темы открытки (ДР — розовый, НГ — ночной синий, «просто так» — персиковый),
до открытия — конверт с сургучной печатью «R$» и штемпелем ROBLOXBANK, кнопка «Открыть письмо»;
после — открытка с почтовой маркой RobloxBank (ссылка на главную), пожеланием рукописным шрифтом
(Caveat, `--font-hand`), кодом и инструкцией. Продажа — одна строка «P.S. Захочешь так же порадовать
друга — открытки живут тут» (`/#gift`). Блоки «Посмотреть коды / Подарить в ответ» убраны. На
компьютере по бокам — связка шаров и вскрытый конверт (≥1100 px). Штемпель и марка — SVG (не текст,
тест типографики). Получателю на «ты» (голос дарителя), инструкции — на «вы».

**♥ Спасибо дарителю.** Сердечко в углу пожелания (есть, если у открытки есть пожелание или «от кого»
и известна почта дарителя: почта чека, иначе подтверждённая почта аккаунта — `giverEmail`). Одно
касание → `POST /api/codes/gift/thanks` → событие `GIFT_THANKS` (уникальный ключ — второго письма не
будет) → дарителю письмо «Подарок … открыт — вам спасибо» с тихим P.S. Работает только после
открытия кода.

**Подарить уже купленный код (19.11.2026)** — `src/lib/codes/gift-share.ts`,
`POST /api/codes/gift/share`. В кабинете у выданного кода (не подарка) кнопка «🎁 Подарить» →
форма: тема, кому, от кого, пожелание (те же правила, что у подарка при покупке: ≤140, без ссылок и
@ников), способ — **ссылкой** (почта не нужна, даритель шлёт сам: «Отправить» через системное меню,
Telegram / WhatsApp / ВКонтакте, копировать) или **письмом** получателю (сразу, без отложенной
отправки). Если код уже показывали — предупреждение «дарите, только если не вводили».
- Заказ остаётся `ACCOUNT`/`EMAIL`; пишутся `gift*` и `giftOpenTokenHash`. Токен —
  HMAC(`code-gift-open:v2:<id>:<соль>`), соль — в событии `GIFT_SHARED` (там же способ и почта
  получателя). Так кабинет может снова показать ссылку (`giftLinksFor`), а в базе — только хеш.
- Пока подарок не открыт — «Вернуть себе» (`action: "revoke"`): хеш и поля открытки стираются,
  ссылка умирает навсегда (новый подарок = новая соль = новая ссылка), событие `GIFT_SHARE_REVOKED`.
- Подаренный код у дарителя скрыт: `/api/codes/reveal` и `/api/codes/resend` отвечают 409, пока
  подарок не вернули. После открытия получателем — «Подарок открыт — код у получателя».
- У подарка, оформленного при покупке (`GIFT`), в кабинете теперь тоже есть ссылка на открытку
  (v1-токен от id) — её можно переслать вручную.

**С 15.11.2026: базовый 1 % = регистрация + подписка на наш канал** (решение владельца — копить трафик в
канал). Подписка проверяется по-настоящему (`src/lib/codes/subscription.ts`): аккаунт с Telegram —
`getChatMember` канала `@Roblox_Bank_Tg` через мост TG-хоста, аккаунт с ВК — `groups.isMember` группы
`bankroblox`; засчитывается любой. Кэш на `User.channelSubscribed/channelCheckedAt` (да — 12 ч, нет —
5 мин), «Я подписался» на сайте и «✅ Я подписался» в ботах проверяют сразу. Аккаунт только с почтой —
предлагаем привязать Telegram. Уровни за друзей (2–5 %) от подписки не зависят.

Прежнее правило: 1 % сразу после регистрации; 3 / 10 / 20 / 30 засчитанных покупателей → 2 / 3 / 4 / 5 %. Уровни
заменяют друг друга. Засчитан = аккаунт, привязанный по ссылке `/r/<код>` (подписанная кука
`rb_ref`, 30 дней; привязка один раз и только НОВОМУ аккаунту), у которого есть выданный и не
возвращённый заказ кода, оплаченный после привязки. Счётчик не хранится — считается запросом
(`countQualifiedInvites`), поэтому повторный webhook не добавляет, а возврат сам убирает.
На витрине крупно — номинал Robux, цена вторым планом; пакет с самой низкой ценой за 1 R$
среди доступных помечен «Выгоднее всего» с ценой за 1 R$ (цифра из той же цены).
Создатель заказа = тот, кто оформил; родитель, оплативший по ссылке, на счёт не влияет и
аккаунт по его email не создаётся. Программа только для кодов.

## Данные (миграция `20261114_activation_codes_store`, аддитивная)

- `CodeOrder` — заказ: `publicId` (`CODE-XXXXXXXX`), суммы, создатель или `recipientEmail`
  гостя, `payTokenHash`, статус `AWAITING_PAYMENT → PAYMENT_PENDING → ISSUED` (или `PAID` при
  пустом складе, `REFUNDED`), срок предложения, отметки письма и показа кода.
- `CodePayment` — попытка оплаты, OrderId у банка `CODE-…-N`, свой email для чека.
- `ActivationCode` — склад: значение только в AES-256-GCM (`ACTIVATION_CODE_ENCRYPTION_KEY`),
  дубли по HMAC; `IN_STOCK → RESERVED (2 ч) → ISSUED`.
- `CodeOrderEvent` — журнал с ключами идемпотентности.
- `User.referralCode / referredById / referredAt`.

Почему не `WbOrder`: там `PENDING` — очередь выкупа геймпасса, оплаченный код попал бы в очереди
админов и ботов.

## Поток денег

1. «Оплатить» → резерв кода (`FOR UPDATE SKIP LOCKED`) → `Init` Т-Банка (тот же терминал, чек
   и классификаторы не менялись) → банк.
2. `/api/webhooks/tinkoff`: подпись и терминал как раньше; `OrderId` с `CODE-` уходит в
   `handleCodePaymentNotification` — сверка PaymentId, суммы, валюты, перехода статуса; код
   выдаётся в той же транзакции, что фиксирует оплату. Возврат браузера ничего не подтверждает.
3. После коммита — письмо (`sendCodeEmail`). Упало — заказ остаётся `ISSUED`, ошибка в
   `emailLastError`, кнопка «Отправить письмо ещё раз» шлёт тот же код.
4. Нет кода после оплаты / второй платёж по оплаченному заказу → пуш в «Уведы» (тема «Нужно
   действие»), деньги — ручной возврат.

Время в сырых SQL склада — только параметром из приложения (не `NOW()`): колонки без пояса,
Prisma пишет UTC. Сквозной тест поймал, что при поясе сессии ≠ UTC последний код уходил двоим.

## API

`GET /api/codes/catalog` · `POST /api/codes/orders` (`self` | `share`) · `POST /api/codes/pay` ·
`POST /api/codes/status` · `POST /api/codes/refresh` · `POST /api/codes/resend` ·
`POST /api/codes/reveal` (только создатель, по сессии) · `GET /r/<код>`. Токен ссылки — всегда в
теле запроса, кроме самого адреса страницы `/pay/<токен>`.

**Оплата работает и без JavaScript (18.11.2026).** Блок «Оплатить» и «Подтвердить за …» на
`/pay/<токен>` — обычные HTML-формы (`method=post` на `/api/codes/pay` и `/api/codes/refresh`).
Со скриптами `onSubmit` перехватывает их и идёт через `fetch`, как раньше; без скриптов (старый
iOS, оборванная загрузка, встроенный браузер) браузер отправляет форму сам. Причина: 17.11
покупатель из TG шесть раз создал заказ и ни разу не смог оплатить. Кнопка была `disabled` до
гидратации, гидратация на его телефоне не случилась, а галочка и поле email работали как обычный
HTML. Кнопка больше не выключается заранее: галочку и email проверяет `pay()` (со скриптами) или
`required` (без них).
- Форма в банк — страница-переход 200 с meta refresh и ссылкой, а не 303: CSP держит
  `form-action 'self'`, и браузеры применяют его к редиректам после отправки формы.
- Ошибка возвращается 303 на `/pay/<токен>?error=<КОД>`, текст берётся из белого списка
  `PAY_FORM_ERRORS` (`src/lib/codes/pay-form.ts`). Свой текст через адрес не подсунуть.
- Форму с чужим `Origin` отклоняем; без `Origin` пропускаем — нужен токен ссылки.
- Телеметрия `/api/observability/client` принимает маршрут `/pay/[token]` — до 18.11 скобки
  давали 400, и ошибки страницы оплаты не доходили до логов.

удалить. Интерфейса склада в TWA пока нет (этап K5 плана).
