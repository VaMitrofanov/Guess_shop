# Почта robloxbank.ru — Brevo SMTP для личного кабинета

**Статус 28.07.2026:** Brevo SMTP и отправитель работают в production, домен
аутентифицирован. Gmail-доставка и verification-ссылка приняты владельцем. Mail.ru
возвращает provider-side `550 spam message rejected`; официальный appeal принят и ждёт
ответа. Входящая почта/MX остаётся отдельной задачей.

Brevo (бывший Sendinblue) используется для транзакционных писем: подтверждения email и
сброса пароля. Бесплатный тариф допускает до 300 писем в сутки — этого достаточно для
текущего объёма личного кабинета.

## Почему Brevo и порт 2525

VPS VDSina блокирует стандартные исходящие SMTP-порты `25`, `465` и `587`. Brevo даёт
SMTP relay на порту `2525`, доступном на хостинге. Приложение уже поддерживает заданные
через env host и port, поэтому изменения кода не нужны.

Почтовый relay отвечает только за **отправку**. Для входящей почты на домен всё равно нужен
почтовый ящик у отдельного провайдера и его MX-записи. До его настройки не заменять
публичный адрес в реквизитах на `@robloxbank.ru`.

## Шаг 1 — Brevo

1. Зарегистрировать бесплатный аккаунт на [Brevo](https://www.brevo.com/).
2. Открыть **Senders, Domains & Dedicated IPs → Domains** и добавить `robloxbank.ru`.
3. Скопировать ровно те DNS-записи SPF и DKIM, которые покажет Brevo для домена.
4. После подтверждения домена открыть **SMTP & API → SMTP**, взять SMTP login и
   сгенерировать SMTP key.

> SMTP key — отдельный секрет для приложения. Это **не** пароль от аккаунта Brevo; не
> отправлять его в чат и не записывать в репозиторий.

## Шаг 2 — DNS в Cloudflare

DNS домена обслуживает Cloudflare. Добавить выданные Brevo записи SPF/DKIM и единственную
DMARC-запись. Все они должны быть в режиме **DNS only**.

| Тип | Имя | Значение |
|---|---|---|
| TXT / CNAME | из Brevo | SPF/DKIM, выданные Brevo для `robloxbank.ru` |
| TXT | `_dmarc` | `v=DMARC1; p=none; rua=mailto:postmaster@robloxbank.ru` |

- SPF должен быть ровно один. Если в домене уже есть `v=spf1`, добавить в него include,
  выданный Brevo, а не создавать второй TXT.
- DMARC начать с `p=none`; ужесточать до `quarantine` или `reject` только после успешной
  живой доставки.
- Не заявлять клиентам адрес `postmaster@robloxbank.ru` как канал поддержки, пока для
  домена не настроен приём почты (MX и ящик).

## Шаг 3 — переменные в Coolify

Добавить переменные только в сервис **Web**. В репозиторий и `.env.example` реальные логин
и ключ не попадают.

```dotenv
SMTP_HOST=smtp-relay.brevo.com
SMTP_PORT=2525
SMTP_USER=<SMTP login из Brevo>
SMTP_PASSWORD=<SMTP key из Brevo>
SMTP_FROM="RobloxBank <noreply@robloxbank.ru>"
```

Текущий `src/lib/mailer.ts` использует именно `SMTP_PASSWORD` и `SMTP_FROM`. Для порта
`2525` он сам включает `secure=false`, поэтому отдельная переменная `SMTP_SECURE` не нужна.
Пока `SMTP_USER` и `SMTP_PASSWORD` не заданы, отправка честно отвечает `not_configured` и
не обещает пользователю несуществующее письмо.

## Шаг 4 — приёмка

После deploy пройти сценарии на настоящих адресах:

1. Регистрация → письмо подтверждения дошло на Yandex, Mail.ru и Gmail, не в спам.
2. Сброс пароля → ссылка одноразовая, действует только 30 минут и после смены пароля
   прежняя сессия отзывается.
3. В headers каждого письма есть `spf=pass`, `dkim=pass`, `dmarc=pass`.
4. В Brevo нет rejected/bounced сообщений для тестов.

Текущая приёмка: Gmail и полный verification-flow — **пройдены**; Mail.ru — **внешний
appeal на рассмотрении**; Yandex — отдельный живой recipient-check не зафиксирован.
Email-регистрация доступна с честным предупреждением о доставке. Входящий ящик
`support@robloxbank.ru` для реквизитов и поддержки настраивается отдельно.
