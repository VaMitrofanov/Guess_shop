# Почта robloxbank.ru — настройка (Яндекс 360 + SMTP для кода)

**Дата:** 2026-07-17. **Статус:** DNS и ящик — на владельце; код отправки готов и
fail-closed до появления кредов.

Зачем это нужно сразу трём вещам:

1. **Личный кабинет** — без писем нет ни подтверждения почты, ни восстановления пароля.
   Сейчас клиент, забывший пароль, не может вернуть доступ сам.
2. **Т‑Банк** — в реквизитах опубликован личный `demidispanov@yandex.com`, при том что ИП —
   Юдина Н. А. Для банка это несоответствие (не на домене, не бьётся по имени).
3. **Приём почты вообще** — у домена нет `MX`, то есть `@robloxbank.ru` сегодня физически
   не принимает письма.

## Исходное состояние (проверено `dig` 17.07)

| Запись | Было |
|---|---|
| `MX` | отсутствует |
| `TXT` / SPF | отсутствует |
| `_dmarc` | отсутствует |
| NS | `adele.ns.cloudflare.com`, `vicky.ns.cloudflare.com` |

DNS живёт в **Cloudflare** — записи добавляются там.

## Шаг 1 — владелец: домен и ящик в Яндекс 360

1. Подключить `robloxbank.ru` в Яндекс 360 для бизнеса.
2. Подтвердить владение доменом — Яндекс выдаст **TXT-запись** (или CNAME) с уникальным
   значением. Добавить её в Cloudflare.
3. Создать ящик **`support@robloxbank.ru`**.
4. Для этого ящика выпустить **пароль приложения** (не основной пароль!) — он нужен коду
   для SMTP.

> Пароль приложения — это отдельный одноразовый секрет для программы. Основной пароль от
> ящика в env класть нельзя: его знает человек, он меняется, и он даёт доступ ко всему
> аккаунту.

## Шаг 2 — DNS в Cloudflare

Значения `MX` и `DKIM` **выдаёт Яндекс** в интерфейсе — подставить их, не выдумывать.
Ниже — что именно должно появиться.

| Тип | Имя | Значение | Прокси |
|---|---|---|---|
| TXT | `@` | подтверждение владения (из Я360) | DNS only |
| MX | `@` | `mx.yandex.net` (приоритет 10) | DNS only |
| TXT | `@` | `v=spf1 include:_spf.yandex.net ~all` | DNS only |
| TXT | `mail._domainkey` | DKIM-ключ из Я360 | DNS only |
| TXT | `_dmarc` | `v=DMARC1; p=none; rua=mailto:support@robloxbank.ru` | DNS only |

Важные детали, на которых обычно спотыкаются:

- **Все почтовые записи — «DNS only»**, не оранжевое облако. Cloudflare-прокси работает
  только для HTTP; для MX/TXT проксирование бессмысленно и мешает.
- **SPF должен быть ровно один.** Два TXT со `v=spf1` = невалидный SPF и письма в спам.
  Если позже добавится второй отправитель — дописывать `include:` в существующую запись, а
  не заводить вторую.
- **DMARC начинать с `p=none`.** Это режим наблюдения: письма не блокируются, но приходят
  отчёты. Ужесточать до `quarantine`/`reject` только после того, как убедились, что своя
  почта проходит с `dkim=pass; spf=pass`. Строгий DMARC на непроверенной настройке
  положит собственную рассылку.
- `~all` (softfail), а не `-all` на старте — по той же причине.

## Шаг 3 — env в Coolify (сервис Web)

Секреты только в env, **не в репозиторий** — он публичный.

| Переменная | Значение | Обяз. |
|---|---|---|
| `SMTP_USER` | `support@robloxbank.ru` | да |
| `SMTP_PASSWORD` | пароль приложения из Я360 | да |
| `SMTP_FROM` | `RobloxBank <support@robloxbank.ru>` | нет (по умолчанию = `SMTP_USER`) |
| `SMTP_HOST` | `smtp.yandex.ru` | нет (дефолт) |
| `SMTP_PORT` | `465` | нет (дефолт, implicit TLS) |

Пока `SMTP_USER`/`SMTP_PASSWORD` не заданы — `src/lib/mailer.ts` считает себя
**невыключенным, а ненастроенным**: `isMailerConfigured()` = false, отправка отказывает с
`not_configured`. Это сделано намеренно: молча «отправить» несуществующее письмо про сброс
пароля хуже, чем честно отказать. Половинчатая конфигурация (есть логин, нет пароля)
трактуется как ненастроенная.

## Шаг 4 — приёмка (не пропускать)

«SMTP ответил 250» ничего не значит. Проверка — **живая доставка**:

1. Письмо на **mail.ru** — дошло, не в спаме.
2. Письмо на **yandex.ru** — дошло, не в спаме.
3. Письмо на **gmail.com** — дошло, не в спаме.
4. В заголовках полученного письма: `dkim=pass`, `spf=pass`, `dmarc=pass`.
5. Ответ на `support@robloxbank.ru` доходит до ящика (проверка `MX`).

Только после п. 1–5 можно:

- менять `email` в `src/lib/legal-details.ts` на `support@robloxbank.ru`;
- включать email-verification в продукте.

> **Порядок обязателен.** Опубликовать `support@robloxbank.ru` в реквизитах раньше, чем
> ящик реально принимает почту, — хуже, чем оставить личный адрес: клиент и банк пишут в
> пустоту. Личный ящик меняем **последним шагом**, когда новый уже работает.

## Что уже готово в коде

- `src/lib/mailer.ts` — тонкий модуль отправки на `nodemailer`, fail-closed без кредов,
  не логирует ни адрес, ни тело, ни токен (адрес — ПД, тело может нести one-time токен).
  Смена провайдера = смена env, никто не импортирует `nodemailer` напрямую.
- `src/__tests__/mailer.test.ts` — 6 тестов: ненастроенность, половинчатая конфигурация,
  пустые значения, дефолты Яндекса, чужой провайдер, битый порт.
- `nodemailer` зафиксирован на **9.0.3**. Это не косметика: версии `<=9.0.0` имеют HIGH-
  advisories (SMTP command injection, CRLF-инъекции в заголовки). npm по умолчанию тянул
  `7.0.13`, потому что `next-auth`/`@auth/core` объявляют nodemailer **опциональным** peer
  с диапазоном `^7.0.7` (мы их email-провайдер не используем). Чтобы получить исправленную
  версию и **не сломать `npm ci` в Docker**, в `package.json` стоит точный pin `9.0.3` +
  `overrides.nodemailer=9.0.3`. Просто поставить `^9` нельзя: `npm ci` падает с `ERESOLVE`,
  то есть деплой не соберётся. Не «упрощать» обратно.
