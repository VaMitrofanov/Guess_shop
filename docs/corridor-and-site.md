# Коридор и сайт (`/guide`)

Точка входа с Wildberries: `robloxbank.ru/guide?source=wb`. Отдельный контейнер (Guide)
обслуживает только этот путь.

## Фазы гейта — `GuideClient.tsx`

`intro → gate → instruction`. Стартовая фаза выбирается по props из `page.tsx`:

| Query | Смысл |
|-------|-------|
| `?source=wb` | WB-коридор: intro/gate, затем единый gamepass guide |
| `?source=site&amount=1000&username=Nick` | единый gamepass guide в режиме SITE; сумма и ник сохраняются до checkout |
| `?source=direct` | тот же актуальный gamepass guide с CTA бота |
| `&skip=1&code=XXXX` | открыть инструкцию напрямую (ссылка от бота; работает в Telegram WebView, где localStorage изолирован) |
| `&test=1` или `code=TESTDEV` | тихий QA-просмотр: без резерва/бота/БД/алертов, кнопки TG/VK **инертны** |
| `&preview=1` | как test, но кнопки **рабочие** («как будто код уже активирован») |
| `&nom=1000` | номинал для test/preview |

Восстановление сессии (`useEffect` при монтировании): `loadWBSession()` из localStorage →
`?code=` из URL → `GET /api/wb-code?code=` → если `claimed` показывает фазу instruction.
Таймаут 10 с на восстановление. Экран восстановления оформлен как дверца цифрового сейфа:
фиолетово-мятная анимация, короткая пасхалка и `prefers-reduced-motion`. CSS-фолбэк через
12 с показывает обновление страницы и прямые TG/VK-ссылки даже без гидрации. Для SITE и
тихих QA-режимов экран не мелькает: восстановление включается только для реального WB flow.

## Визуальный вход, темы и motion (13.07.2026)

- `WBIntro` переведён в Violet / Frost: полноэкранное спасибо за покупку, явная кнопка
  «Активировать код», автоматический переход через 6,5 с и статичный режим при
  `prefers-reduced-motion`.
- `WBGate` теперь использует тот же визуальный язык, что главная и checkout: на desktop
  это приветственный блок + карточка активации в две колонки, на узком экране — один
  линейный поток без горизонтального скролла. API, резерв кода и TG/VK handoff не менялись.
- Глобальный переключатель темы предлагает `Светлая / Тёмная / Как в системе`, сохраняет
  выбор в `localStorage` (`robloxbank-theme`) и отслеживает изменение системной темы в
  auto-режиме. Токены живут в `globals.css`; новые storefront, checkout, SITE guide и WB
  flow имеют полноценные dark-варианты.
- Для WB и SITE инструкций используется актуальная медиа-основа из `public/guide`, а не
  старые нарисованные копии Creator Hub. Поверх скриншотов добавлены мягкий zoom, focus-
  затемнение, пульсирующая рамка и подпись нужного элемента. Все loop-анимации выключаются
  через `prefers-reduced-motion`, при этом статическая обводка остаётся.
- Визуальный язык анимационных focus-layer сверяется с официальными источниками Roblox:
  [Passes — Roblox Creator Hub](https://create.roblox.com/docs/production/monetization/passes),
  официальный dark UI Creator Hub и карточка `⋯ / Copy Asset ID` из документации. Внутри
  демонстраций используются Roblox-blue `#335fff`, neutral dark surfaces, белая типографика
  и tap-ripple; зелёный RobloxBank остаётся только во внешнем shell, чтобы не смешивать
  интерфейсы двух продуктов. Путь шагов соответствует официальному `Creations →
  Monetization → Passes → Create pass → Sales → Item for Sale → Price → Save Changes`.
- QA URL без побочных эффектов: `/guide?source=wb&test=1&nom=1000`. Для проверки живого
  вида с рабочими CTA по-прежнему используется `preview=1`.
- Portrait QA: media-колонки WB-инструкции включаются только от `860px`; на более узком
  viewport шаги идут одной колонкой. Первый шаг сокращён до основного действия и двух
  компактных browser-подсказок. Для light theme warning-карточка и hero-gradient имеют
  отдельные контрастные цвета — тёмные значения больше не наследуются как бледный текст.

### RobloxBank как цифровой сейф — финальный проход редизайна

- Фирменная метафора — **цифровой сейф для Robux**: на главной появился крупный фоновой
  vault-door, банковский штамп RobloxBank и единая фиолетово-мятная система статусов.
  Иконка вкладки (`app/icon.svg`) и Apple icon используют ту же дверцу сейфа с `R$`.
- После выбора пакета калькулятор сразу просит ник Roblox. Для авторизованного клиента
  `/api/account/me` подставляет сохранённый ник, но поле остаётся редактируемым. Главный CTA
  ведёт сразу в `/checkout?amount=…&username=…`: инструкция больше не является обязательной
  остановкой до проверки уже готовых геймпассов.
- WBGate подчёркивает поле кода двумя расходящимися focus-ring, подписью «Введи код сюда»
  и увеличенным mobile input. Поле получает focus при открытии; reduced-motion оставляет
  статичную рамку без циклического движения. Grid-элементы имеют `min-width: 0`, поэтому
  карточка и широкое поле кода не подрезаются на viewport 390 px.
- `/guarantees`, `/reviews`, `/faq` и `/dashboard` переведены со старого pixel/dark shell
  на общий Violet/Frost язык: крупные заголовки, rounded cards, safe/seal элементы,
  читаемые CTA и базовый размер смыслового текста 15–20 px.
- Checkout и единый guide получили увеличенные подписи, подсказки, карточки выбора и legal
  текст. Измеренный desktop baseline инструкции: основной текст `17 px`, поля `18 px`,
  figcaption `16 px`, overlay-метки `13–17 px`; на зелёных success-поверхностях используется
  тёмный текст или отдельная контрастная light-theme палитра.
- Фоновая окружность hero заменена на заметную CSS-дверцу сейфа с болтами и вращающимся
  штурвалом; reduced-motion оставляет её статичной.

## Инструкции WB и сайта

- `WB`, `SITE` и `BOT` обслуживает один `GuideClient → WBInstructionV2`. Девять шагов,
  assets, Managed pricing warning, расчёт и поиск больше не копируются; различаются только
  заголовок, фиксированный/редактируемый номинал и финальный handoff.
- В режиме SITE желаемая сумма редактируется только в расчёте шага 7 и ограничена единым
  диапазоном `CUSTOM_MIN=100` / `CUSTOM_MAX=100 000`. Финал ведёт в
  `/checkout?amount=…&username=…&gamepassId=…`, поэтому выбранный пасс не нужно искать снова.
- Checkout реализует search-first: по нику вызывает агрегирующий
  `/api/roblox/gamepasses`, показывает **все** публичные пассы на продажу, сортирует ближайшие
  к ожидаемой gross-цене наверх и автоматически выбирает единственное совпадение. Состояния
  `user not found`, `no gamepasses`, `wrong price` сохраняют сумму/ник и дают явный fallback
  в инструкцию. Выбор промежуточной игры из пользовательского пути удалён.
- `src/lib/gamepass-search-view.ts` фиксирует общую сортировку и channel-specific match:
  SITE требует точную цену канонического checkout, WB/BOT сохраняют допуск buyout ±2 R$.
  Contract-тест защищает от скрытия неподходящих, но полезных для диагностики пассов.
- Инициализация темы теперь детерминирована (`auto/light` на SSR и первом client render),
  а `localStorage`/`matchMedia` читаются после mount — SITE guide больше не получает
  hydration mismatch `Sun ↔ Moon`.

## WBGate — ввод кода

- Поле нормализует ввод: `[^a-zA-Z0-9] → ""`, upper-case, 7 символов.
- `validateAndPersist()` → `POST /api/wb-code` (резерв) → сохраняет сессию + cookie `wb_code`.
- Обе кнопки (TG/VK) вызываются с `guide=true`:
  - **TG:** редирект `t.me/RobloxBankBot?start=wbg_КОД_SESSIONID` (`wbg_` = guide-режим).
  - **VK:** показывает `VKAuthButton` с `wbCode = GD+КОД` (`GD` = guide-режим).
- Fallback-контакт менеджера `@RobloxBank_PA` на ошибках и внизу карточки.

> Замечание: в текущей вёрстке «чистый» `wb_`-префикс (не guide) с гейта не отправляется —
> обе кнопки всегда guide. Обработчик `wb_` в боте остаётся для прямых/старых ссылок.

### VK-кнопка и CSP — обязательная сверка хостов

VK-кнопка работает через self-hosted VK ID SDK (`public/vendor/vkid-sdk-2.6.5.js`),
который строит свои эндпоинты от домена **`vk.ru`** (`id.vk.ru`, `oauth.vk.ru`,
`api.vk.ru`, `login.vk.ru`), а не `vk.com`. Content-Security-Policy сайта и Guide-сборки
(`next-security.ts`, общий для обоих контейнеров) обязан включать эти хосты в
`connect-src` и `frame-src` — иначе обмен OAuth-кода блокируется браузером молча, и
клиент после окна VK видит «Ошибка авторизации», хотя все серверные роуты здоровы.
При обновлении vendored SDK или правке CSP сверять список хостов (риск №16 в
[security.md](security.md)). Диагностика: ошибки видны только в браузерной консоли
(CSP violation), на сервере следов нет; страница и `/api/wb-code` при этом отвечают 200.

Смежная эксплуатационная деталь: HTML гейта отдаёт Guide-контейнер, статика идёт через
префикс `/_next-guide` (Traefik → Guide), поэтому смоук «страница 200» не доказывает
работоспособность JS — проверять нужно и чанки из HTML, и фактический VK-вход.

Оба класса поломок ловятся автоматически: контракт-тест
`src/__tests__/csp-vk-hosts.test.ts` (CI) и синтетический смоук
`node scripts/smoke-corridor.mjs` (страница+чанки+SDK+CSP+API; флаги `--reserve`,
`--alert`, `--base=`) — прогонять после каждого деплоя Web/Guide.

## API коридора

### `POST /api/wb-code` — резерв кода
Атомарно в транзакции: находит код (case-insensitive), проверяет статус и возвращает
`denomination`. Логика:
- `isUsed && userId` → 409 «уже активирован».
- `CLAIMED && !isUsed` → 409 `BOT_CLAIMED` («продолжай в боте»).
- `RESERVED` тем же sessionId → продлевает бронь; другим sessionId → **перехватывает**
  (клиент держит физическую карту — он «выигрывает»).
- `AVAILABLE` → `RESERVED` на +60 мин.

### `GET /api/wb-code?code=` — статус
Возвращает `{ claimed, denomination, platform, orderStatus, robloxUsername }`. `claimed`
= есть `userId` или статус `CLAIMED`. Данные заказа — чтобы инструкция показала один
правильный канал и статус «заказ уже оформлен».

### `POST /api/wb-code/select-gamepass` — материализация заказа (one-tap с сайта)
Пользователь выбрал геймпасс в поиске по нику на шаге 9. Роут промотирует provisional-заказ
`AWAITING_GAMEPASS → PENDING` прямо здесь (не дожидаясь возврата в бота) и шлёт админ-карточку
«🌐 ONE-TAP С САЙТА». Идемпотентно (guard по статусу в транзакции → карточка ровно раз).
Серверная ре-валидация: цена ±2 R$ и `isActive`; если Roblox недоступен — принимает
(`validationSkipped`), как бот.

### `GET /api/roblox/gamepasses?query=&code=` — поиск по нику/ID
`extractGamepassId()` парсит URL/чистый ID → прямой lookup; иначе `getUserGamepasses(nick)`.
Если пусто — доп. `getRobloxUser` чтобы отличить «нет такого юзера» от «есть, но нет
публичных геймпассов на продаже» (зеркалит ветвление бота).

Опциональный `code` (гайд передаёт его при поиске с шага 9): если ник подтверждён Roblox'ом,
роут сразу отмечает его на заказе — `noteProbableNickByCode` (`src/lib/capture-nick.ts`)
дописывает `[НИК? дата] ник (site-search)` в `adminNote`. Ранний захват ника: менеджер видит
вероятный ник ещё до того, как клиент дошлёт геймпасс (кейс VFNCQMT). В основное поле
`robloxUsername` вероятный ник **не** пишется — только подтверждённые пути (валидация
геймпасса, one-tap выбор).

### `GET /api/wb-link` — коридор сайт → VK
Читает `wb_code` из JWT-сессии (записан при VK-логине в `auth.ts`), линкует `userId`
к `WbCode` (если ещё не CLAIMED), редиректит в `vk.me/club237309399?ref=КОД` (или `GD+КОД`).

## Поток активации (сайт → TG)

```
1. /guide?source=wb → WBIntro → WBGate
2. Ввод 7-символьного кода → "Получить в Telegram"
3. POST /api/wb-code → RESERVED; редирект t.me/RobloxBankBot?start=wbg_КОД_SESSIONID
4. TG /start: upsert User → provisional TX (WbCode CLAIMED isUsed=false + WbOrder AWAITING_GAMEPASS)
   → админ-уведомление «НОВЫЙ КЛИЕНТ» → (опц.) гейт подписки → кнопка «ОТКРЫТЬ ИНСТРУКЦИЮ»
   ⭐ если на сайте уже выбран геймпасс (selectedGamepassId) → one-tap «✅ Да, выкупаем»
5. Клиент проходит 9 шагов, создаёт геймпасс на create.roblox.com
6. Вариант А (осн.): на сайте вводит ник → поиск → выбор → select-gamepass → one-tap в бот
   Вариант Б: пишет ник/ссылку/Asset ID прямо в бот
7. processGamepassSubmission: extractPassId → getGamepassDetails (4 эндпоинта) →
   проверки isActive / цена ±2 / не private. Roblox недоступен → validationSkipped
8. Финальная TX: WbCode.isUsed=true, WbOrder → PENDING, gamepassUrl сохранён
9. Клиент получает подтверждение; renderOrderCard → все ADMIN_IDS
10. Менеджер: ✅ ВЫКУПЛЕНО → COMPLETED → уведомление; ❌ ОШИБКА → причина → уведомление
```

**Сайт → VK** — аналогично, но через VK-логин (`auth.ts` создаёт provisional-заказ и шлёт
TG-уведомление «КОД АКТИВИРОВАН (сайт → VK)»), затем `vk.me/...?ref=КОД` →
`handleRefActivation`.

⚠️ **Шов «VK-логин без диалога» (закрыт 2026-07-06).** VK-логин на сайте создаёт юзера, но
НЕ диалог с сообществом: если человек не нажмёт «Начать» в чате, бот не сможет писать (VK 901,
клиент недостижим — см. кейс PDRC54J). Поэтому `VKAuthButton` (order mode) после успешного
логина больше не редиректит в VK молча: показывается interstitial **«Код привязан! …
Обязательно нажми „Начать" и разреши сообщения от сообщества — туда придут статус заказа и
выплата»** с явной кнопкой «Открыть диалог VK» (`vk.me/club…?ref=КОД`). Недостижимых
клиентов менеджер видит в TWA — красный бейдж «🚫 Бот не может написать (VK)» в карточке
заказа (см. `docs/twa-admin.md`), плюс разовый скан `scripts/report-unreachable.mjs`.

**Прямой ввод в бот (без сайта):** 7-символьный текст → тот же provisional-паттерн.

## TG-уведомления при VK-логине на сайте (`src/auth.ts`, провайдер `vk-id`)

Каждый успешный VK ID-логин на сайте шлёт карточку во все `TG_CHAT_ID`. Какая карточка —
зависит от контекста:

| Карточка | Когда |
|----------|-------|
| `📦 ЗАКАЗ #…` (полная, с кнопкой дашборда) | только «живая» активация: передан `wb_code`, код существует и заказ ещё `AWAITING_GAMEPASS` |
| `🆕 Новый пользователь` | первый VK-логин (юзер только что создан) без активной активации |
| `🔑 Вход` | повторный VK-логин без активной активации |

`🔑 Вход` — **штатное информационное уведомление**, не ошибка и не атака. Типичный источник:
клиент с заказом в `PENDING`/`COMPLETED` возвращается на сайт проверить статус (в т.ч. заново
открывает `/guide` со старым cookie `wb_code` — раз заказ уже не `AWAITING_GAMEPASS`, вместо
карточки заказа уходит именно короткая карточка входа). По VK ID из карточки юзер ищется в БД:
`SELECT … FROM "User" WHERE "vkId" = '<id>'` → его заказы в `WbOrder.userId`.

**Имя «VK User»** — исторически клиентский fallback из `VKAuthButton.tsx` (декод JWT
`id_token` на клиенте; при неудаче — `VK User`, и `authorize()` затирал реальное имя в БД).
**Исправлено 2026-07-03** (риск #5 в `docs/security.md`): личность теперь резолвится на
сервере через VK `user_info`/`public_info` (`src/lib/vk-id.ts`), имя берётся из ответа VK, а
`User.name`/`image` обновляются только непустыми значениями — пустой ответ VK больше не
затирает имя. Ранее «застрявшие» как `VK User` (~3 из 120) перезапишутся при следующем входе.

**Личный кабинет:** `/dashboard` читает legacy `Order` и `WbOrder` всех источников. Вход
доступен через server-verified VK и TG; свежая web-сессия может привязать TG, а если subject
уже владеет legacy-профилем — безопасно объединить его заказы и бонусы с audit trail.
