Сторонних счётчиков (Яндекс Метрика, Google Analytics) на сайте нет. Журнал прокси пишет IP,
время, страницу и код ответа. Источник перехода и браузер в нём не сохраняются: эти поля всегда «-».

### Как устроена своя аналитика
- **Клиент** (`src/components/site-observability.tsx`): на каждый просмотр страницы, один раз за
  сессию, отправляет `type: "visit"`. В сигнале:
  - тип устройства — по User-Agent и touch;
  - встроенный браузер — Telegram, ВК, Instagram;
  - источник — по `document.referrer` и `?source=wb` / `?code=`;
  - анонимный id — случайные 8 hex в `localStorage`.

  Админка и TWA не считаются.
- **Сервер** (`/api/observability/client`): пишет посещение в `PerformanceSample` со
  `surface = "site-visit"`. Поля:
  - `metric = "<устройство>:<источник>"`;
  - `rating` = встроенный браузер;
  - `fingerprint` = анонимный id.

  Миграции не было.
- **События витрины** (`src/lib/site-track.ts`, с 18.11.2026): `type: "event"`, пишутся в
  `PerformanceSample` со `surface = "site-event"`, `metric` = событие, `rating` = значение,
  `fingerprint` = тот же анонимный id. Каждое событие с тем же значением — раз за сессию вкладки.

  | Событие | Когда | Значение |
  |---|---|---|
  | `pack` | выбрал номинал кода кликом | номинал |
  | `gift_on` | включил «В подарок» | — |
  | `buy_click` | нажал «Купить» / «Подарить» / «Ссылка родителю» | номинал |
  | `order` | заказ кода создан (дальше — банк) | `CODE-…` — по нему отчёт узнаёт оплату из `CodeOrder` |
  | `section` | долистал до блока главной (верх блока выше 2/3 экрана) | `codes`, `trust`, `calculator`, `compare`, `reviews`, `gift`, `invite`, `bottom` (атрибут `data-section` в `page.tsx`) |
  | `gp_amount` | выбрал сумму в калькуляторе геймпасса | сумма |
  | `gp_checkout` | нажал «Проверить и оформить» | сумма |

  Лимит приёма сигналов поднят до 40 подряд и 1 в 2 с на IP (было 20 и 1 в 3 с).
- **Отчёт** — `src/lib/site-visits.ts`: `loadVisitReport` (посещения) и `loadFunnelReport`
  (воронка) — по одному запросу к базе на срез.

### Раздел «Посетители» (`/admin/visitors`)
- **Без гейта инструкции:** «потенциальные» (открыли хоть что-то кроме `/guide`, `/pending`, `/wb/…`),
  «только инструкция», «покупатели WB, заглянувшие на витрину» (пришли по WB-ссылке и открыли витрину).
- **Воронка кодов:** потенциальные → открыли главную → долистали до кодов → выбрали номинал →
  нажали «Купить» → заказ создан → оплатили. 800 выбран по умолчанию, поэтому шаг «выбрали кликом»
  бывает меньше следующего.
- **Откуда пришли → покупка:** первый внешний источник посетителя за период (WB, ВК, Telegram,
  Яндекс, Google, прямой) и сколько из них нажали «Купить» и оплатили.
- **Глубина прокрутки:** доля открывших главную, кто долистал до каждого блока.
- **Номиналы:** выбрали / нажали «Купить» / оплачено.
- **Брошенная оплата:** по `CodeOrder` за период — создано, оплачено, брошено (не оплачено дольше
  часа) по номиналам (все заказы, не только с сайта) и по устройствам (только заказы с событием `order`).
- **Геймпасс и подарок:** долистали до калькулятора, выбрали сумму, нажали «оформить», открыли
  `/checkout`; включили «В подарок».
- **Приватность:** IP и cookies не используются, id случайный и живёт только в браузере.

## Что ещё можно подключить
- **Яндекс Метрика** — устройства, источники, вебвизор (запись сессий), карта кликов. Для РФ это
  стандарт. Нужен аккаунт владельца (номер счётчика в env). Кроме того, нужны строка в политике
  конфиденциальности и разрешение домена `mc.yandex.ru` в CSP.
- **User-Agent и Referer в журнале прокси** — настройка Traefik (`accesslog.fields.headers`);
  меняется с перезапуском прокси.
